# 色切り替え協力ランナー(ColorSwitchRunner)

> **1台のスマートフォンを2人で共有して遊ぶ、新感覚の協力型2Dランゲーム**

## 開発状況

🚧 プロトタイプ開発中
（2026年12月〜2027年1月完成予定）


## 🎮 概要

「色切り替え協力ランナー」は，**ジャンプ担当**と**色切り替え担当**に役割を分担し，協力してゴールを目指す横スクロールアクションゲームである．

プレイヤーは赤・青2種類の床をリアルタイムで切り替えながらゴールを目指す．

* **1人プレイ**

  * 左手：ジャンプ
  * 右手：色切り替え
  * マルチタスクを楽しめる

* **2人プレイ**

  * Jump担当
  * Switch担当
  * 声を掛け合いながら協力するゲーム体験

---


# 開発コンセプト

「誰でもすぐ遊べる操作性」と「協力によるコミュニケーション」を両立した，
短時間でも繰り返し遊びたくなるゲーム体験を目指して開発を進める．

---

# 💡 面白さの核

本作の面白さは「異なる役割を持つ2人の意思決定を同期させる協力体験」にある．

一般的な協力ゲームでは，各プレイヤーが独立して操作することが多いが，本作では1台の端末を共有し，異なる情報と役割を持つ2人が同時に判断する．

Jump担当は移動タイミング，Switch担当は床状態の管理を担当するため，単独では突破できない状況が生まれる．

「いつジャンプするか」「いつ色を切り替えるか」という短時間の意思決定を共有することで，自然なコミュニケーションと成功時の大きな達成感を生み出す．

# ゲームの特徴

## ① 役割分担による協力プレイ

* Jump担当
* Switch担当

という2つの役割に分かれてプレイする．

片方の判断ミスがゲームオーバーに直結するため，自然なコミュニケーションが生まれる．

---

## ② シンプルな操作

* ジャンプボタン
* 色切り替えボタン

操作はこの2つだけである．

ゲーム初心者でもすぐ遊ぶことができる．

---

# レベルデザイン方針

本作では，ステージ構成によってプレイヤーの判断・協力・達成感を段階的に引き出すことを目的としている．

単純に難易度を上げるのではなく，新しい要素を少しずつ導入し，プレイヤーが理解・挑戦・成功を繰り返せる設計を行う．

| 要素 | 目的と狙う体験 |
| --- | --- |
| 基本ステージ | ジャンプと色切り替えの基本操作を理解する |
| 色切り替え床 | 2人でタイミングを合わせる協力体験を生み出す |
| ホールド床 | 状況判断と役割分担の重要性を高める |
| 操作反転 | 瞬間的な判断力とコミュニケーションを要求する |
| テンポ変化 | 緊張感や集中力を生み出す |
| ゴーストシステム | 自分の成長を実感し，再挑戦する動機を作る |

---

# プレイヤー体験設計

本作では，プレイヤーが「理解する → 協力する → 挑戦する → 達成感を得る」という体験サイクルを繰り返せることを重視している．

単に高難度なステージを作るのではなく，プレイヤー自身が成長を実感し，2人の連携によって成功を掴む過程に面白さを感じられる設計を目指す．


## ① 初見でも理解できる導入

序盤では基本操作のみを使用し，プレイヤーが「ジャンプ」と「色切り替え」の役割を自然に理解できる構成とする．

初めから複雑な判断を要求するのではなく，安全なステージで成功体験を積むことで，ゲームシステムへの理解と継続意欲を高める．


## ② 協力による意思決定の創出

本作では，2人が異なる役割を担当するため，一方の操作だけではクリアできない状況を意図的に作り出す．

例えば，

- Jump担当が移動タイミングを判断する
- Switch担当が床状態を管理する
- お互いに次の行動を予測して声を掛け合う

という協力を必要とすることで，単なる同時プレイではなく「2人で攻略している」という体験を生み出す．


## ③ 難易度上昇による判断量の増加

ステージ後半では，新しいギミックを追加することで，単純な操作難度ではなくプレイヤーが考える要素を増加させる．

| 段階 | 導入要素 | プレイヤー体験 |
| --- | --- | --- |
| 初級 | 赤青床 | 色切り替えの基本理解 |
| 中級 | 複数色床・ホールド床 | 役割分担とタイミング判断 |
| 上級 | 操作反転・テンポ変化 | 瞬間的な判断と適応力 |
| 高難度 | 複数ギミック組み合わせ | 2人で攻略方法を考える楽しさ |

難しいだけではなく，「失敗理由が分かる」「次は成功できそう」と感じられる難易度調整を行う．


## ④ 成功体験と再挑戦意欲の設計

本作では，失敗をストレスではなく成長につながる体験として設計する．

死亡地点表示やゴーストシステムにより，

「どこで失敗したか」
「前回より改善できたか」

をプレイヤー自身が理解できるようにする．

試行錯誤による改善を促し，クリア時には「自分たちの連携で突破した」という達成感を得られることを目標とする．


## ⑤ 1人プレイと2人プレイの異なる体験

本作では，同じステージでもプレイ人数によって異なる楽しさを提供する．

### 1人プレイ

2つの操作を同時に管理することで，

- 判断速度
- マルチタスク能力
- 操作精度

が求められる高難度アクションとして楽しめる．


### 2人プレイ

役割分担によって，

- 声掛け
- 状況共有
- タイミング合わせ

が重要となり，協力による達成感を楽しめる．


## レベルデザインにおける評価指標

プレイヤー体験を定量的に評価するため，以下の項目をテストプレイで確認する．

| 評価項目 | 確認する内容 |
| --- | --- |
| クリア率 | 難易度が適切か |
| 平均リトライ回数 | 挑戦意欲が維持されているか |
| 死亡地点 | 難所や改善点の分析 |
| 初見プレイ時間 | 操作理解度 |
| 2人プレイ満足度 | 協力体験の有無 |
| 再挑戦意欲 | リプレイ性 |

取得した結果をもとにステージ配置やギミックの調整を行い，プレイヤーが自然に挑戦したくなるゲーム体験を目指す．

## 感情曲線設計

ステージ全体では，プレイヤーの感情変化を意識した構成を行う．

| フェーズ | プレイヤーの感情 | 設計意図 |
| --- | --- | --- |
| 導入 | 理解・安心 | 基本操作を習得する |
| 中盤 | 緊張・協力 | 役割分担の重要性を体験する |
| 難所 | 焦り・集中 | 瞬間判断による緊張感を生む |
| クリア | 達成感・共有 | 2人で突破した成功体験を提供する |

単純な難易度上昇ではなく，感情の起伏を設計することで，最後まで挑戦したくなる体験を目指す．


# 開発の特徴

## データ駆動型ステージ

```
CSV
      ↓
CSVLoader
      ↓
StageGenerator
      ↓
Unity Stage
```

レベルデザインをコードを書き換えずに変更できる．
